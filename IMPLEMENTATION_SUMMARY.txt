💾 FIRESTORE SCHEMA:

admins/{uid}
├─ email: string
├─ name: string
├─ password: hashed string (use bcrypt in production)
├─ role: "admin"
├─ permissions: string[]
├─ status: "active" | "inactive"
├─ createdAt: ISO timestamp
├─ updatedAt: ISO timestamp
└─ lastLogin: ISO timestamp or null

providers/{uid} (ENHANCED)
├─ [existing fields: uid, email, fullName, specialization, etc.]
├─ status: "pending_verification" | "verified" | "rejected"
├─ policiesAccepted: boolean
├─ createdAt: ISO timestamp
├─ verifiedAt: ISO timestamp or null
├─ verificationNotes: string or null
├─ approvedBy: email or null
├─ rejectedAt: ISO timestamp or null
├─ rejectionReason: string or null
├─ rejectedBy: email or null
└─ updatedAt: ISO timestamp

adminAudits/{auditId} (NEW)
├─ action: "provider_approved" | "provider_rejected"
├─ providerUid: string
├─ approvedBy: email
├─ notes: string
├─ timestamp: ISO timestamp
└─ status: "verified" | "rejected"

📞 SUPPORT & TROUBLESHOOTING:

ADMIN LOGIN ISSUES:
1. Verify admin credentials in Firestore admins collection
2. Check Firebase authentication configuration
3. Ensure Firestore security rules allow admin access
4. Check browser console for specific error messages

PROVIDER LIST NOT LOADING:
1. Verify providers collection exists
2. Check provider documents have required fields
3. Review Firestore security rules
4. Check browser network tab for API errors

APPROVE/REJECT NOT WORKING:
1. Verify admin has write permission
2. Check Firestore security rules
3. Ensure provider document exists
4. Check that status field is updatable

1. Check browser performance tab
2. Verify Firestore indexes are created
3. Monitor network requests
4. Review bundle size
